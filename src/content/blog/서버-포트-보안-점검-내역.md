> 서버에 문제가 생겨 리부트 시켰을 때 특정 서비스 동작이 이상하다는 문의를 받아 점검을 진행.

### 점검한 내역들

1. 리부트가 안되었다 해서 시스템 설정 파일 검사

```plain
systemctl cat 서비스명
```

> 설정 내용 확인 시 파이썬 api 서버에 Restart 옵션이 `on-failure` (비정상적 종료일 때만 재시작) 로 되어져 있어서 문제가 발생한 것으로 추측

2. 현재 서비스들이 전체적으로 정상 동작 중인지 확인

```plain
systemctl status 서비스명1 서비스명2 서비스명3

systemctl status 서비스명1 서비스명2 서비스명3 | grep -E "active|running" # grep 으로 전체 내용이 아닌 동작 중인지만 확인 가능
```

3. 열려 있는 포트 리스트

```plain
ss -lntp | grep -E "9111|8000"
```

4. 서비스 중인 것 리스트

```plain
systemctl list-units --type=service
```

**systemctl list-units**

> systemd가 관리하는 현재 유닛 목록을 확인하는 명령임
> 기본적으로 로드된 유닛 중 활성 상태인 유닛을 중심으로 보여준다.

- 주요 옵션

| 옵션 | 의미 |
| --- | --- |
| `-all` | 비활성 유닛까지 포함해서 표시 |
| `--type=service` | 서비스 유닛만 표시 |
| `--type=socket` | 소켓 유닛만 표시 |
| `--type=target` | 타깃 유닛만 표시 |
| `--state-running` | 실행 중인 유닛만 표시 |
| `--state=failed` | 실패 상태인 유닛만 표시 |
| `--failed` | 실패한 유닛만 표시 |
| `--no-pager` | 결과를 페이지 단위로 나누지 않고 출력 |
| `--plain` | 트리 형태 등 특수한 출력 형식 없이 표시 |
| `--no-legend` | 상단 설명 및 하단 요약 정보 생략 |

4. SSH 키 조사

> 이전에 운영 서버 증설 작업 시 파일을 rsync 로 옮겨올 떄 OTP 설정으로 인해 바로 끊기는 문제가 발생했음. 그래서 OTP 대신 다른 인증 수단이 필요해서 만들어 놓았었음. **(관련 내용 추가 포스팅)**

```plain
ls -al ~/.ssh/id_rsc *
```

- `-a` : 숨김 파일까지 모두 출력
- `-l` : 상세 정보 형태로 출력
- `~` : 현재 사용자의 `홈` 디렉터리
- `/` : 디렉터리 경로 구분자.

**`~` 는 로그인한 사용자의 홈 디렉터리를 의미**

5. 접속 기록 확인

```plain
last -20
```

6. 실패한 서비스

```plain
systemctl -=failed
```

7. 부팅 에러 로그 확인

```plain
journalctl -b -p err | tail -100
```

> journalctl 자체에서 마지막 100개 로그 항목 출력함.

- `-b` : 현재 부팅 로그
- `-p err` : 오류 수준이 err 인 로그 조회
- `tail` : 입력된 내용의 마지막 부분 출력
- `-100` : 마지막 100줄 출력

8. 기동 과정 로그 확인

```plain
journalctl -b -0 | grep -iE "comfyui|fail"
```

- `-b` : 특정 부팅 시점의 로그 조회
- `-0` : 현재 부팅 시점 (-1, -2, 1 각각 직전 부팅, 두 번 전 부팅, 다음 부팅 기록)
- `|` : 앞 명령의 결과를 뒤 명령으로 전달
- `grep` : 특정 문자열 검색
- `-i` : 대소문자 구분 없이 검색
- `-E` : 확장 정규표현식 사용
- `"fail|test"` : fail 또는 test 가 포함된 문자열 검색
