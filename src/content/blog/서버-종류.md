## 1. 서버는 GPU 서버와 CPU 서버만 있는 게 아니다

> 먼저 알아야할 건 GPU 서버와 CPU 서버의 역할을 구분하는 것 보단, 주요 연산 자원이 무엇인지 구분하기.

**실제 서비스에서는 여러 종류의 서버를 목적에 맞게 구성한다.**

- 웹 서버 / Reverse Proxy : Nginx, Apache, HTTPS, 요청 전달.
- 애플리케이션 서버 : Sprint, FastAPI, 비즈니스 로직, API 처리
- CPU 서버 : DB, 일반 연산, 작업 관리
- GPU 서버 : AI 모델 추론, 이미지, 영상 생성
- 스토리지 / 데이터베이스 : MySQL, PostgreSQL, Redis, NAS, Object Storage

## 2. CPU 서버와 GPU 서버는 언제 사용?

**CPU 서버**

> 다양한 종류의 작업을 순차적 또는 병렬적으로 처리할 수 있는 범용 프로세서

| 활용 분야 | 구체적인 작업 |
| --- | --- |
| 웹 서버 | Nginx, Apache |
| API 서버 | Spring, FastAPI |
| 데이터베이스 | MySQL, PostgreSQL |
| 파일 처리 | 파일 업로드, 압축, 변환 |
| 일반 연산 | 데이터 가공, 비즈니스 로직 |
| 배치 작업 | 정기적인 데이터 집계 |
| 시스템 운영 | 모니터링, 로그 수집 |
| 캐시 | Redis |

ex. 회사의 일반적인 관리자 페이지

- 사용자 로그인
- 회원 정보 조회
- 게시글 등록
- DB 데이터 검색
- 통계 데이터 계산
- 파일 업로드

> 이런 작업은 대부분 CPU 서버에서 처리할 수 있다.

**Q : 그럼 CPU 서버로 AI 모델 실행이 가능?**
**A : 가능. 다만 모델과 작업량에 따라 속도 차이가 크다.**

ex. CPU로 AI 모델 가능한 작업

- 작은 머신러닝 모델 추론
- OCR
- 텍스트 분류
- 경량 이미지 처리
- 임베딩 생성

> 반면 대규모 이미ㅣ 생성, 영상 생성, LLM 추론은 GPU가 훨씬 유리한 경우가 많다.

**GPU 서버**

> GPU 는 동일하거나 유사한 연산을 대량으로 병렬 처리하는데 강점이 있다.

| 활용 분야 | 구체적인 작업 |
| --- | --- |
| 이미지 생성 | Stable Diffusion, Flux |
| 영상 생성 | LTX, Minimax 계열 모델 |
| LLM | LLM 추론 및 파인튜닝 |
| OCR | 딥러닝 기반 문서 인식 |
| 음성 AI | 음성 인식, 음성 합성 |
| 컴퓨터 비전 | 객체 탐지, 이미지 분석 |

**GPU 서버라고 해서 CPU 가 필요없는 건 아니다.**

- CPU : 요청 처리, 데이터 전처리, 작업관리
- RAM : 모델 로딩 및 일반 메모리 관리
- GPU VRAM : 모델 가중치와 추론에 필요한 데이터 저장
- GPU : AI 모델의 주요 연산 수행
- SSD : 모델 파일, 결과물, 캐시 저장

**그 외에 알아두면 좋은 서버의 종류들**

| 서버 종류 | 주요 역할 | 대표 기술 |
| --- | --- | --- |
| Web Server | HTTP 요청 처리 및 전달 | Nginx, Apache |
| WAS / API Server | 애플리케이션 로직 실행 | Spring, FastAPI |
| DB Server | 데이터 저장 및 조회 | MySQL, PostgreSQL |
| Cache Server | 빠른 데이터 접근 | Redis |
| Storage Server | 파일 및 데이터 저장 | NAS, MinIO |
| GPU Server | AI 모델 실행 | CUDA, PyTorch |
| Proxy Server | 요청 중계 및 접근 제어 | Nginx, HAProxy |
| Monitoring Server | 시스템 상태 수집 및 시각화 | Prometheus, Grafana |
| Queue / Worker Server | 비동기 작업 처리 | RabbitMQ, Celery |

## 3. 서버를 관리하려면 어떤 지식이 필요한지?

> 서버 관리라 하면 Linux 명령만 잘 사용하면 될 것 같지만, 실제로는 여러 분야의 지식이 필요함.

**운영체제 및 Linux 기본**

> 서버를 관리하려면 운영체제가 어떻게 동작하는지 이해해야된다.

| 학습 항목 | 알아야 할 내용 |
| --- | --- |
| Linux 구조 | Kernel, Shell, User Space |
| 파일 시스템 | /etc, /var, /home, /opt, /data |
| 권한 관리 | chmod, chown, sudo |
| 사용자 관리 | useradd, passwd, groups |
| 프로세스 | ps, top, htop, kill |
| 서비스 | systemctl, systemd |
| 패키지 관리 | apt, yum, dnf |
| 로그 | journalctl, /var/log |
| 환경변수 | PATH, LD_LIBRARY_PATH |
| 셸 스크립트 | Bash, .sh 자동화 |

ex. GPU 서버에 FastAPI를 설치했다 가정.

- FastAPI 프로세스가 현재 실행 중인지?
- 어떤 포트에서 대기하고 있는지?
- 서버가 재부팅 되면 자동으로 실행되는지?
- 프로그램에서 오류가 발생하면 어디서 로그가 관리되는지?
- 프로세스가 종료되지 않는다면 어떻게 처리되는지?
- 특정 사용자에게만 디렉터리 접근 권한을 줄 수 있는지?

**네트워크**

- 서버는 혼자 동작하지 않는다. 다른 서버나 외부 사용자와 통신해야됨.
- 이 부분을 모르면 서버에 프로그램을 설치해도 외부에서 접근할 수 없는 상황이 발생함.

| 학습 항목 | 알아야 할 내용 |
| --- | --- |
| IP | 공인 IP, 사설 IP |
| Port | 80, 443, 8000, 9111 등 |
| TCP / UDP | 통신 방식 |
| DNS | 도메인과 IP 연결 |
| HTTP / HTTPS | 웹 통신 |
| SSH | 원격 서버 접속 |
| Firewall | 방화벽 및 포트 허용 |
| Reverse Proxy | Nginx, Apache |
| SSL/TLS | HTTPS 인증서 |
| Routing | 네트워크 경로 |

ex. 현재 회사의 GPU 서버에 FastAPI가 9111 포트로 실행 중. 그런데 외부에서 접속이 안 되면 다음을 확인.

1. FastAPI 프로세스가 실행 중인지?
2. 9111 포트에 정상적으로 바인딩되어져 있는지?
3. 서버의 방화벽에서 9111을 허용했는지?
4. 중간에 있는 Apache나 Nginx 에서 요청을 차단하고 있지 않은지?
5. 서버 간 네트워크 연결이 가능한지?

이렇게 문제를 계층별로 추적할 줄 알아야됨
