4. 프록시 우회

> `/etc/https/conf.d/ss.conf` 경로에 있는 건 일반적으로 Apache 웹 서버를 사용하는 Linux 환경임

**/etc/httpd/ 는 어떤 경로?**

> Linux 서버에서 `/etc` 는 시스템 및 프로그램의 설정 파일을 보관하는 디렉터리이다.

```plain
/etc/
 ㄴ httpd/
 ㄴ conf/
 ㄴ httpd.conf
 ㄴ conf.d/
			ㄴ ssl.conf
			ㄴ welcome.conf
			ㄴ custom.conf
		ㄴ conf.modules.d/
			ㄴ 00-base.conf

```

- `/etc/httpd/` : Apache 전체 설정 디렉터리
- `httpd.conf` : Apache의 메인 설정 파일
- `conf.d/` : 추가 설정 파일을 분리해서 관리하는 디렉터리
- `ssl.conf` : HTTPS 및 SSL / TLS 관련 설정
- `conf.modules.d/` : Apache 모듈 로드 설정

즉, `httpd.conf` 가 메인 설정이고 `conf.d` 는 기능별 설정을 분리하는 공간이라고 이해하기

**`ssl.conf` 의 역할**

> Apache 에서 HTTPS 통신을 처리하기 위한 설정 파일

- 관리하는 것
    - HTTPS 포트(443) 설정
    - SSL / TLS 인증서 경로
    - 개인키 경로
    - 가상 호스트(VirtualHose) 설정
    - HTTPS 요청 처리

```plain
// ex. Apache가 443 포트에서 HTTPS 요청을 받을 수 있도록 해주는 것. 
Listen 443 https

<VirtualHost *:443>
	ServerName example.com
	
	SSLEngine on
	
	SSLCertificateFile /etc/pki/tls/certs/server.crt
	SSLCertificateKeyFile /etc/pki/tls/private/server.key
</VirtualHost>
```

**프록시 설정을 `ssl.conf` 에 작성하는 이유**

- `ssl.conf` 는 일단 프록시 전용 파일은 아니다.
- 다만 HTTPS 요청을 처리하는 `<VirtualHost *:443>` 내부에서 프록시 설정을 함께 작성할 수 있다.

ex. Apache 에서 Tomcat 으로 요청을 전달한다 가정

```plain
<VirtualHost *:443>
	ServerName example.com
	
	SSLEngine on
	
	SSLCertificateFile /etc/pki/tls/certs/server.crt
	SSLCertificateKeyFile /etc/pki/tls/private/server.key
	
	ProxyPreserveHost On
	
	ProxyPass	/api http://localhost:8080/api
	ProxyPassReverse /api http://localhost:8080/api
</VirtualHost>
```

- ProxyPass : 클라이언트의 요청을 다른 서버로 전달
- ProxyPassReverse : 백엔드 서버의 응답에 포함된 리다이렉트 주소 등을 조정

### 설정 이후 동작

- 사용자가 [`https://example.com/api/users`](https://example.com/api/users) 요청
- Apache 가 HTTPS 요청을 받음
- Apache가 요청을 [`http://localhost:8000/api/users`](http://localhost:8000/api/users) 로 전달
- Tomcat이 API 처리
- Apache를 거쳐 클라이언트에 응답

이렇게 구성하여 `Reverse Proxy `구현해봄
