**ping 확인 및 해결할 수 있는 문제들**

- 서버가 켜져 있는지 확인할 수 있는지?
- 서버까지 네트워크가 연결되어 있는지 확인 가능한지
- 패킷이 얼마나 정상적으로 전달되는지 알 수 있는지?
- 패킷 손실이 발생하는 원인을 찾을 수 있는지?
- `ping` 으로 서버의 포트나 서비스까지 확인할 수 있는지?

### ping 이란?

> 네트워크를 통해 특정 대상에게 작은 요청 패킷을 보내고, 응답이 돌아오는지 확인하는 명령

**정확히는 ICMP 프로토콜을 이용해서 대상과의 네트워크 연결 상태 및 응답 시간을 확인하는 도구**

**ping 동작 방식**

> 내 PC -> GPU 서버 로 요청 전송 시 GPU 서버에서 응답 패킷이 반환되는데. 요청과 응답이 오가는 데 걸린 시간 및 성공, 실패 여부를 측정한다.

- `ping` 은 일반적인 웹 요청처럼 `HTTP` 를 사용하는 게 아닌, 웹 서버나 FastAPI 를 실행하지 않아도 네트워크 장비와 운영체제가 ICMP 요청에 응답할 수 있다.

### ping이 사용하는 ICMP란?

> 네트워크 통신에는 여러 프로토콜이 있다.

|프로토콜|주요 역할|
|---|---|
|`IP`|패킷을 목적지까지 전달|
|`TCP`|신뢰성 있는 데이터를 전송|
|`UDP`|연결 설정 없이 데이터 전송|
|`ICMP`|네트워크 상태 및 오류 정보 전달|

**`ping` 은 `ICMP`의 두 가지 메시지를 사용한다.**
- ICMP Echo Request : 상대방에게 보내는 요청
- ICMP Echo Reply : 상대방이 보내는 응답

> 즉, ping 은 상대방에게 내가 보낸 요청이 네트워크를 통해 도착했는지? 응답을 돌려줄 수 있는지? 확인하는 방식이다.

### 기본 ping 명령어 사용 방법
```
ping 192.168,0,100
```
또는 서버의 IP 주소나 도메인 입력을 사용.
```
ping 8.8.8.8
ping google.com
```

**서버에 연결되는지 확인**
> GPU 서버의 IP가 `192.168.10.50` 이라면

```
ping 192.168.10.50
```

결과는 다음과 비슷하게 나올 수 있다.
```
PING 192.168.10.50 (192.168.10.50): 56 data bytes
64 bytes from 192.168.10.50: icmp_seq=0 ttl=64 time=1.234 ms
64 bytes from 192.168.10.50: icmp_seq=1 ttl=64 time=1.102 ms
64 bytes from 192.168.10.50: icmp_seq=2 ttl=64 time=1.310 ms
```
- `64 bytes` : ICMP 응답 패킷 크기
- `icmp_seq=0` : 요청 패킷의 순번
- `ttl=64` : 응답 IP 패킷의 남은 TTL
- `time=1.234 ms` : 요청을 보내고 응답을 받기까지 걸린 시간

**여기서 `time` 이 중요하다.**
- `time=1.234 ms` 라면 내 PC 에서 서버로 요청을 보내고 다시 응답을 받기까지 약 1.2 밀리초가 걸렸다는 의미
- 이를 `RTT (Round Trip Time, 왕복 시간) 이라고 한다.

**TTL 이란?**
> Time To Live 약자로 IP 패킷이 네트워크를 무한히 돌아다니지 않도록 제한하는 값이다. 패킷이 라우터를 하나 통과할 때마다 일반적으로 TTL이 1씩 감소한다.

ex. 내 PC -> 라우터 A -> 라우터 B -> GPU 서버
- 처음 TTL이 64였다면 서버에 도착할 때는 62가 될 수 있다.
- 다만 서버에 응답할 때 TTL을 새로 설정하기 때문에, ping 결과의 TTL 만으로 정확히 몇 개의 라우터를 거쳤는지 판단하기 어렵다.

### ping 으로 인터넷 연결 확인하기
```
ping 8.8.8.8
```

- `8.8.8.8` 은 Google 에서 제공하는 공개 DNS 서버 IP 주소임.
- 이 IP에 ping 응답이 온다면 적어도 해당 목적지까지 IP 네트워크 통신이 가능하다는 뜻이다.

- 하지만 `ping` 이 성공했다고 인터넷의 모든 서비스가 정상인 것은 아니다.
```
내 PC
  ↓
인터넷 연결
  ↓
8.8.8.8 응답 성공
  ↓
특정 웹사이트 접속 실패
```
이런 상황도 발생 가능. 왜냐면 ping 은 `ICMP` 를 확인하는 것이고, 웹사이트는 일반적으로 TCP와 HTTP/HTTPS를 사용하기 때문이다.

### ping 옵션 정리
**`-c` : 요청 횟수 지정**
```
ping -c 10. 192.168.15.30
```

- 10개의 요청을 보내고 종료한다.
- Linux 에서 기본적으로 ping 이 계속 실행되지만, `-c` 를 사용하면 정해진 횟수만 검사할 수 있음

**`-i` : 요청 간격 지정**
```
ping -i 0.5 -c 10 192.168.10.50
```
- 0.5초 간격으로 10번 요청을 보내는 명령이다.
- 기본 간격은 일반적인 Linux 환경에서는 1초이다.

**`-s` : 요청 데이터 크기 지정**
```
ping -s 1000 -c 10 192.168.17.30
```
- ping 요청에 포함되는 데이터 크기를 `1000바이트` 로 설정한다.
- 기본 ping 은 작은 패킷을 보내기 때문에, 작은 패킷은 잘 전달되지만 큰 패킷은 전달되지 않는 문제를 발견하지 못할 수도 있다.

** `-W` : 응답 대기 시간 지정**
```
ping -W 2 -c 10 192.168.19.50
```

- 응답을 기다리는 시간을 2초로 설정한다.
- 네트워크가 느리거나 응답이 지연되는 상황에서 사용.

### ping 결과에서 패킷 손실 확인하기
- 예시 결과
```
10 packets transmitted, 6 received, 40% packet loss
rtt min/avg/max/mdev = 1.1/2.3/5.7/1.4 ms

# ex. 60% 손실은 아래같은 상황
10 packets transmitted
4 received
6 packets lost
60% packet loss
```

- ping 요청 10개 중 6개에 대해 응답을 받지 못했다는 뜻.
- 정상적인 네트워크에서 지속적으로 60^ 손실이 발생한다면 심각하게 조사해봐야됨.

**RTT 통계 해석하기**
```
rtt min/avg/max/mdev = 1.1/2.3/5.7/1.4 ms
```
|항목|의미|
|---|---|
|`min`|가장 짧은 왕복 시간|
|`avg`|평균 왕복 시간|
|`max`|가장 긴 왕복 시간|
|`mdev`|왕복 시간의 변동 정도|

- 예시로 평균 RTT는 2ms 인데 최대 RTT 가 500ms라면, 평소에 빠르지만 간헐적으로 네트워크가 크게 지연되는 상황일 수도 있다.
- Linux ping 통계는 패킷 손실과 왕복 시간 변동을 확인하는데 사용된다.
